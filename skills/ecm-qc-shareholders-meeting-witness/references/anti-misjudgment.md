# 批注前防误判（Anti-Misjudgment）

两类高频错位批注的防控：**模板章节锚点**（误判"重复/应删除"）和**自动编号
识别**（误判"编号缺失/错位"）。对应 SKILL.md 硬规则 9、10。

---

# 第一部分 模板章节锚点

典型翻车（九联科技 2025 年年度股东会）：AI 看到「（一）本次股东会的召开」
项下的网络投票程序性表述，误以为与「（一）出席本次股东会的人员资格」项下
"参与网络投票的股东共 X 名……"重复，批了"建议删除"——实际两段职能不同、
并存是行业通行结构，**批注就是错的**。

**硬规则**：写"建议删除某段""该段不应在此处""与下文重复"类批注前，必须
先对照本部分 §三速查表；如属固定章节内容、表述符合该章节职能，**不要批注**。

## 一、标准三章 + 结论意见结构

金杜系（含其他主流律所）见证意见均遵循：

```
[标题页 / 抬头 / 致函]
[引言段：律所身份 + 委托关系 + 法规依据 + 委托范围]
[审查文件清单]
[声明事项段：保证段 + 见证范围 + 同意公告]

一、本次股东会的召集、召开程序
   （一）召集　（二）召开　[召集召开结论意见段]
二、出席本次股东会会议人员资格与召集人资格
   （一）出席人员资格　（二）召集人资格
三、本次股东会的表决程序、表决结果
   （一）表决程序　（二）表决结果　[表决程序与结果结论意见段]
四、结论意见

[签章页：律所盖章 + 经办律师签字 + 律所负责人签字 + 日期]
```

章节顺序、标题行业内基本固定——**不应建议调整章节顺序或合并章节**。

## 二、各章节必备要素

**一（一）召集**：1. 董事会决议日期 + 届次 + 议案（《关于召开 XXXX 股东会的
议案》）+ 决定召开日期；2. 通知披露日期 + 媒介（巨潮/交易所网站/指定报刊）。

**一（二）召开**：1. 召开方式（现场+网络）；2. 现场会议时间、**地点（与通知
逐字一致）**、主持人；3. 网络投票时间（交易系统 9:15-9:25、9:30-11:30、
13:00-15:00；互联网投票 9:15-15:00）；4.（可选）实际召开与通知一致核查段。
末尾召集召开结论意见段（"……履行了法定程序，符合……规定"）。

**二（一）出席人员资格**（按顺序 7 个要素）：

1. **现场出席统计**——律所核查股东名册、机构股东持股证明/法定代表人证明/
   授权委托书、自然人股东持股证明/身份证明/授权委托书后，确认"现场出席的
   股东及股东代理人共【X】人，代表有表决权股份【X】股，占【X】%"
2. **网络投票出席统计（数字段）**——"根据 [深圳证券信息有限公司/上证所信息
   网络有限公司] 向公司提供的网络投票结果，参与本次股东会网络投票的股东共
   【X】名，代表有表决权股份【X】股，占【X】%"
3. **中小投资者口径**——"其中，除公司董事、高级管理人员以及单独或合计持有
   公司 5% 以上股份股东以外的股东（以下简称中小投资者）共【X】人……"
4. **合计出席统计**
5. **列席人员**（董事、董事会秘书、高级管理人员、律师；监事一般已无，残留
   按软处理核实，见第三部分与 `voting-rules.md` §四）
6. **网络投票资格依赖系统验证段**（律所声明无法自行核查、依赖系统验证）
7. **出席人员结论意见段**

> 本节第 2 条是**列示数字**的固定位置。不要因第三章表决程序项下出现"通过……
> 行使表决权"程序性表述就以为重复——见 §四 Pair 1。

**二（二）召集人资格**：召集人（董事会/审计委员会/股东请求）+ 资格符合性结论。

**三（一）表决程序**（按顺序 4 条程序性表述）：

1. 议案与通知相符、无修改或新增议案
2. 现场表决方式（记名投票）+ 计票监票（股东代表 + 律师共同进行）
3. **网络投票程序段**——"参与网络投票的股东在规定的网络投票时间内通过
   [交易所] 交易系统或互联网投票平台行使了表决权，网络投票结束后，[信息网络
   有限公司] 向公司提供了网络投票的统计数据文件"
4. 主持人结合现场 + 网络投票统计结果宣布表决情况

> 第 3 条只描述"怎么行使表决权 + 数据怎么提供"，**不**列具体数字——数字在
> 二（一）第 2 条。两段并存是行业通行结构。

**三（二）表决结果**：各议案表决结果段（议案标题 + 同意/反对/弃权票数及
占比 + 中小投资者口径 + 特别决议表述 + 关联回避说明）+ 表决程序与结果结论
意见段（"……表决结果合法、有效"）。

**四、结论意见**：综合性结论——召集召开程序、出席人员与召集人资格、表决
程序与表决结果，全部合法有效。

## 四、易误判为"重复"的典型对

- **Pair 1：网络投票"程序段"（三（一）3）vs "数字段"（二（一）2）**——
  前者描述股东"如何"行使表决权和数据"如何"获取，后者列示"多少"股东
  参与。并存是行业通行结构，**不要批删除/重复/合并**。
- **Pair 2：召开方式（一（二）1）vs 表决方式（三（一）2）**——都涉及
  "现场+网络"，但前者说"会议如何开"，后者说"表决如何进行"（含计票
  监票）。**不要批重复**。
- **Pair 3：网络投票时间（一（二）3）vs 网络投票程序（三（一）3）**——
  前者列具体起止时点，后者描述行权过程。**不要批合并**。

# 第二部分 自动编号识别

项目组常把 Word 自动编号（`<w:numPr>` + `numbering.xml`）和手动文本编号
（`<w:t>` 里直接写"一、""（二）"）混搭。只看文本会误判：

> **典型场景**（申通 2025 年度股东会）：P42 有 `numId=22, lvlText="（%1）"`
> → Word 渲染为"（一）本次股东会的表决程序"；P47 无 numPr、文本直接写
> "（二）本次股东会的表决结果"。只看文本会误以为"P47 是（二），前面没有
> （一）"——其实 P42 自动编号就是（一），视觉完全连贯，**不该批**。

| 项目组写法 | `<w:t>` 看到的 | 实际渲染 | 误判 |
|---|---|---|---|
| 自动 "1." → 手动 "2." | "" → "2." | "1." → "2." | "前面没有 1" |
| 自动 "一、" → 手动 "二、" | "" → "二、" | "一、" → "二、" | "缺一、" |
| 手动 "（一）" → 自动 "（二）" | "（一）" → "" | "（一）" → "（二）" | "缺（二）" |

## 硬规则与命令

写"编号不一致/编号错/编号缺失"类批注前，**必须**先跑脚本核对渲染后编号：

```bash
python3 scripts/render_paragraphs.py /path/to/file.docx              # 全文
python3 scripts/render_paragraphs.py /path/to/file.docx --para 47    # 单段详情
python3 scripts/render_paragraphs.py /path/to/file.docx --numbering-summary
```

输出示例（每段一行）：

```
P 42 [（一）] (numId=22 L0)  本次股东会的表决程序     ← 自动编号
P 47                        （二）本次股东会的表决结果 ← 手动文本（无 numId）
```

方括号 = 自动编号渲染值；无方括号 = 纯手动文本。脚本覆盖 CJK 全部格式
（一二三、（一）（二）、1. 2. 3. 等）。

## 决策逻辑

1. **渲染后连贯 → 不批注**。源码混搭也不是内核审查范围。
2. **渲染后跳号/错位/重复 → 【必改】**并指出正确编号。例：P31 自动渲染
   "2."，P32 手动写"4." → 【必改】"4."应为"3."。
3. **渲染一致但源码混搭 → 默认不批**；项目组有体例规范要求的最多【建议】
   统一为全自动或全手动，避免后续插入段落导致错位。
4. **跨章节编号格式不一致 → 看渲染结果**：如"一、二、三、"后出现"4. 结论
   意见"（换了编号体系或手动写错）→ 【必改】统一为"四、"。

## issue 清单标记

Step 2 整理 issue 时，任何涉及编号的疑问标记"⚠ 需核对自动编号"，跑脚本
确认后再决定保留或删除该条：

```
Issue 草稿：P47 编号"（二）"前面缺"（一）"  ⚠ 需核对自动编号
  → render_paragraphs.py --para 42 → P42 自动编号"（一）" → 删除本条
```

# 第三部分 措辞 / 格式 / 相关性类误判（高频，来自专业内核反馈）

下列情形**默认不批**；确需提示的按指定降级处理。每条都来自资深律师实测
反馈，是 skill"过度挑错"的主要来源——内核要替代人，就要先不犯这些。

## 一、"出席"vs"列席"不是口径不一（**不批**）

董事、董事会秘书用"**出席**"，公司高级管理人员用"**列席**"，是《公司法》
《上市公司股东会规则》的**惯用、正确**区分（董事是会议组成人员故"出席"，
高管非组成人员故"列席"），**不得**当成"口径不一致/表述前后不统一"批注。

> 实战误判（强瑞技术）：见证意见对董事、董秘用"出席"、对高管用"列席"，
> 被误批"口径不一，请统一表述"——**错误**，这正是规范写法。

- 只有当**同一类人员**在同一份意见书里时而"出席"时而"列席"（真矛盾）才提示。
- "出席/列席"对象范围与《会议通知》载明范围是否一致，属事实核对（可做），
  但**不要**把"董事出席、高管列席"本身说成需要统一的问题。

## 二、字号 / 字体 / 排版类一致性（**默认不批**）

纯文本提取与 document.xml 中的 `w:sz`/`w:rFonts` **不能可靠还原 Word 渲染后
的视觉字号/字体**（受样式继承、主题字体、东亚/西文分别设置、`w:szCs` 等影响），
据此判断"字号不一致/字体不统一/某行偏大偏小"**极易误判**。

> 实战误判（东方盛虹）：签字页两个签名"陈复安""祁慧"被批"字号不一致"——
> 资深律师核实**并无字号不一致**。

**硬规则**：

- **禁止**输出"字号不一致 / 字体不统一 / 行距缩进异常 / 某处明显偏大偏小"
  这类纯视觉排版批注，**尤其禁止【必改】**。
- 排版美观、字号、字体、对齐、空行多寡一律**不属内核审查范围**。
- 仅当排版差异**直接造成歧义或信息错误**（如表格串列导致票数张冠李戴）时，
  才以**【建议】**提示，并须说清"差异导致了什么实质问题"，不能只说"不一致"。

## 三、法规 / 定义的细微措辞差异（**不批，除非影响实质**）

- **法规修订年份**：见证意见对法规是否加注"（XXXX 修订）"属体例细节。**不要
  建议项目组给某法规补注修订年份**（标错年份风险更大）。见证意见内部有的法规
  标了年份、有的没标，至多以**【建议】**提示"统一体例（建议一律不标注修订
  年份，以现行有效版本为准）"，**绝不**【必改】要求补具体年份。详见
  `checklists.md` §三第 3 项与本 skill"不臆断年份"硬规则。
- **"中小投资者"定义的措辞差异**：通知里"中小投资者"定义含"及其一致行动人"
  而见证意见未含（或反之）——**这种定义措辞细节差异默认不批**。只有当该差异
  **实际改变了单独计票的分母人群或票数结果**时才提示，且必须**具体说明**
  "因为 X，导致单独计票分母/结果应为 Y"，**不得**写"口径不一致，请核实"这类
  看不懂的批注（见第五部分"批注可读性"）。

> 实战误判（众泰汽车）：一条"中小投资者定义含'及其一致行动人'，与本段口径
> 不一致……请确保与深证信口径一致"的批注，资深律师反馈"这条批注具体含义
> 是什么？"——**看不懂、也无实质影响，应不批或重写为具体问题**。

## 四、精确区分"会议通知 / 会议记录 / 会议决议"（**别张冠李戴，别提低价值点**）

- 三类底稿文件名称含义不同，**引用时必须用准确名称**：**会议通知**（召开前
  发出的通知）、**会议记录/纪要**（会议过程记录）、**会议决议（公告）**（表决
  结果文件）。不要把"会议通知"写成"会议记录"。
- **底稿内部的细枝末节**（如董事会决议与会议记录里"通知发出日"差一两天、
  扫描件内部某页序号笔误）**对见证意见结论通常无实质影响**——默认**不批**，
  确有必要至多**【底稿】**轻提，**不要**升级成"两者矛盾，请核实"式的强批注。

> 实战反馈（澄天伟业）：一条关于"《会议记录》载明通知 X 日发出、与决议矛盾"
> 的【核实】批注，资深律师指出"这里的会议记录可能指会议通知，对意见书意义
> 不大"——**既混淆了文件名称，又属低价值点**。

## 五、批注可读性与相关性（贯穿全局的两道闸）

写每一条批注前，过这两道闸，过不了就删：

1. **可读性闸**：一个**没看过原文**的资深律师，能否仅凭这条批注**一眼看懂
   问题是什么、改成什么**？做不到就重写——**点明确切差异内容、引用原文字句、
   给可执行改法**，禁止"口径不一致""体例不统一""请确保一致"这类空话。
2. **相关性闸**：这条问题**是否影响见证意见对召集召开/出席资格/表决程序/
   表决结果的判断**？纯底稿细节、排版美观、定义措辞、与结论无关的内部小瑕疵
   → **不批**（噪音会淹没真正的硬伤，降低内核可信度）。

> 内核替代人的标准不是"挑出最多的点"，而是"挑出的每一点都对、都看得懂、
> 都值得改"。宁可少批一条边缘问题，不可错批一条规范写法。
